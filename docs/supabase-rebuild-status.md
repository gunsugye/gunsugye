# Supabase 기반 재구축 현황

## 2026-11-28 구현 진행

새 앱 소스는 `rebuild/`, 독립 빌드 결과는 `docs/next/`이다. `scripts/build-rebuild.mjs`로 빌드한다. 기존 전체 배포 스크립트와 분리했다.

- 업무일지, 명단(총기번호), 생활실 방 관리: Supabase 직접 조회·추가·수정·삭제 구현. 50건 단위 조회, 중대/상태 필터 제공.
- 실제 프로젝트에 `app2_members`, `app2_journal`, `app2_people`, `app2_rooms`와 RLS 적용. 실인원과 과거 업무 자료는 미입력.
- 중대 계정은 일반학기 자기 중대만 조회하며 추가·수정·삭제 불가. DB 트랜잭션 테스트를 롤백하여 검증.
- 저장 버전 충돌 감지, 중복 저장 방지, 오류 시 입력 유지. 팝업은 우측 삭제/취소/저장, 열람 전용은 확인만 표시.
- 단위 테스트 5개와 PC 1280px·모바일 390px 브라우저 시뮬레이션 통과. 브라우저 테스트는 가상 API로 UI를 검증하며 실사용자 로그인 테스트를 대신하지 않는다.
- Supabase Auth Google 로그인 코드 연결. 실제 Auth API는 로컬 연결 시간 초과로 검증 미완료. Google 제공자 및 리디렉션 설정 확인 필요.

나머지 업무 메뉴, 개인 앱, 혼합 생활실 입주자 배정, 권한 관리 UI, 데이터 이관은 남아 있다. 전체 앱 교체·운영 전환을 완료한 상태는 아니다. 아래는 이전 조사 기록이다.

현재 앱의 데이터는 Supabase에 저장되지만 업무 처리에는 Apps Script, 화면 배포에는 GitHub Pages와 Cloudflare가 사용된다. 사용자가 운영 중단 및 Supabase 기반 재구축을 요청했다. 기존 데이터베이스의 삭제나 운영 경로 전환은 아직 수행하지 않았다.

2026-11-28 읽기 전용 조회: 운영 데이터셋 revision 2949, 3개 파일, 67개 탭, 28,496행. 기존 시트 복원 작업 기록은 revision 913으로, 그 이후의 운영 기록까지 포함한다고 볼 수 없다.

`scripts/rebuild-private-foundation.sql`은 신규 인원·군수품·수정 요청 테이블의 일부 초안이다. 실제 프로젝트에서 트랜잭션을 롤백하는 방식으로 SQL 실행 가능 여부만 확인했다. 운영에 적용되지 않았으며 인증, 권한, 모든 기존 기능과 데이터 이전 도구가 없어 완성된 앱이 아니다.

전환에 필요한 작업:

1. 최신 운영 데이터·첨부·설정·이력을 일관된 시점에 백업하고 복구를 검증한다.
2. 사용자별 인증, 30일 세션, 관리자 및 중대별 권한을 서버에서 구현하고 격리 데이터로 검증한다.
3. 생활실·총기·군수품·피복·업무일지·사역 등 기존 기능과 전수조사 및 수정 요청을 새 저장 구조에 이식한다.
4. 원본 시트와 최신 DB 값을 비교하여 이관하고 누락·충돌을 확인한다.
5. 개인 및 관리자 화면을 새 API에 연결하고 GitHub 외의 화면 제공 경로를 마련한다.
6. 접힌 항목 후순위 조회, 동시 접속·저장, 복구 및 모바일 동작을 검증한 뒤 운영 주소를 전환한다.

Google Forms와 Google Sheets 연동은 이후 별도 Apps Script로 구현한다. 기존 운영 자료나 기록은 새 앱 검증 전에 삭제하지 않는다.
